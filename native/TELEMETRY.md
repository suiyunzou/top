# 原生传感器与 CPU 口径

CPU 与 DRAM 采样和换算由 ftop 的 C++ 代码完成；通过官方签名 PawnIO 驱动和 IntelMSR 模块读取五个 MSR。风扇使用联想 WMI 只读方法，GPU 使用 NVIDIA NVML。自研驱动已退出正式构建。

## 数据范围

| 指标 | 计算方法 | 范围 |
| --- | --- | --- |
| 进程 CPU | Δ进程用户与内核时间 / Δ系统用户与内核时间 × 100% | 整机计算时间容量。分母包含空闲时间。 |
| 总 CPU | (Δ系统总时间 − Δ空闲时间) / Δ系统总时间 × 100% | 整机 0–100%。不是随频率变化的 Processor Utility。 |
| CPU 温度 | MSR 0x1A2 的 TjMax − MSR 0x1B1 的数字温差 | CPU 封装。必须检查温度有效位。 |
| CPU 功耗 | uint32(新能量 − 旧能量) × 2^(-能量单位指数) / Δ单调时钟 | CPU 封装平均功耗。不是插座或整机功耗。 |
| 物理内存 | GlobalMemoryStatusEx：总量 − 可用量 | 二进制 GiB。进程内存是工作集，含共享页，不能相加当作整机已用内存。 |
| 内存读写带宽 | Intel MCHBAR 0x5050/0x5054 的 32 位计数差 × 64 / Δ单调时钟 | 全部内存控制器流量，含其他设备访问；不是进程读写量、缓存流量或理论峰值。十进制 MB/s / GB/s，仅在内存悬停详情显示。 |
| 分页文件 | EnumPageFiles：各分页文件 TotalInUse × 页大小 | 已占用分页文件容量，不是提交量，也不是当前换页速率。 |
| 网络速率 | 活跃接口收发累计字节之差 / 接口采样间隔 | 排除常见虚拟接口；十进制 KB/s、MB/s。 |
| GPU | 已安装 NVIDIA 驱动的 NVML 接口 | 利用率、显存、温度、频率和功耗；只显示所选首块 NVIDIA GPU。显存优先用 v2，系统保留量单列；旧驱动退回 v1 时明确标注含保留量。 |
| CPU 频率 | PDH Processor Performance × 注册表标称频率 | 活跃周期频率估计，不是含休眠时间的有效频率。 |
| 磁盘活动与速率 | PDH PhysicalDisk(_Total)：100 − % Idle Time、Disk Read/Write Bytes/sec | 物理磁盘汇总；活动时间是多磁盘平均值，读写为合计。首次建立基线或读取失败显示“—”。 |
| 内存功耗 | MSR 0x619 的低 32 位能量增量 × 能量单位 / Δ单调时钟 | DRAM 域合计，不按内存条数重复累加。RAPL 硬件估计；非外部功率计实测。 |
| 整机功耗 | 暂无整机功耗传感器 | 原始读数保持未知；开启估算后显示“≈”。不将 CPU 与 GPU 合计冒充整机功耗。 |

能量单位来自 MSR 0x606 的位 12:8。能量计数来自 0x611 的低 32 位。温度上限来自 0x1A2 的位 23:16。温差来自 0x1B1 的位 22:16，有效位为 31。

12 个逻辑处理器中占满一个，进程显示约 8.3%。旧实现显示约 100%。上游 ftop 也已在 [CPU 归一化修复](https://github.com/Nongfsq/ftop/commit/d5e860b54a90af67f3acb2142b9b28b9ba88624f) 中统一显示口径。

进程枚举与总时间基线配对。枚举失败时清空基线，并显示未知。PID 创建时间变化时重新建立基线。首次采样不伪造 0%。进程退出、采样先后顺序和计时分辨率会使进程之和与总 CPU 略有差异。

## 开销与失效行为

- 温度和能量每秒读取一次，温度上限和能量单位在初始化时读取并缓存。功耗时间戳取能量读取前后用户态 QPC 的中点。
- 固定驱动句柄和栈上请求缓冲。稳定传感器读取不扫描设备、不分配堆内存。
- 采样在现有后台线程中完成。读取时临时绑定一个允许的逻辑处理器，随后恢复。
- 隐藏窗口时暂停详细采样，恢复后重新建立能量基线。
- 驱动缺失时最多每 30 秒重试。读取失败时显示未知，不沿用旧数值。
- 首次能量读取、时间倒退、采样间隔超过 10 秒、异常功率和不安全回绕窗口均不输出功耗。
- 应用只允许读取 0x1A2、0x1B1、0x606、0x611、0x619，不调用写入函数。PawnIO 本身是通用硬件访问驱动；不能将其描述为专门的只读驱动。
- 内存、分页、GPU、逐线程 CPU、频率、网络采样失败时显示未知；不保留旧值，不把分页失败当成零。网络采用接口查询时刻，避免其他采样工作的耗时改变速率分母。

## 安装与诊断

官方 PawnIO 2.2.0 安装程序和签名 IntelMSR 模块直接嵌入 EXE。构建时校验固定 SHA-256 和安装程序 Authenticode 签名。首次启动复用已安装驱动，未安装时从受限临时目录运行内置安装程序；运行前再次校验签名。安装路径不下载网络文件，不改系统启动或签名策略，也不自动重启。`--install-sensors` 可显式执行同一个内置安装程序。

EXE 清单要求管理员权限；取消 UAC 则不启动。权限用于取得硬件访问权，基础统计公式不变。安装和采样失败时显示错误或未知，不伪造零值。

`--sample-report <绝对输出路径> <2至120个样本>` 可以输出 CPU、传感器、内存、GPU、网络、错误码和耗时，并包含原始系统时间、MSR、接口计数和单调时钟，用于独立重算。该模式不打开界面，不输出进程名称或路径。只有显式调用该诊断参数才写报告。

`--self-test` 包含温度有效位、计数回绕、首次基线、长时间间隔、CPU 分母与枚举失败后的基线清除测试。

目前 CPU 温度与功耗适配 Intel Comet Lake A5/A6、单封装、单处理器组。其他型号尚未开放，不能保证所有电脑有温度。


## 真实风扇转速（2026-10-13）

在支持的联想设备上，`ROOT\WMI:LENOVO_GAMEZONE_DATA` 可在管理员权限下提供风扇读数。只调用 `GetFanCount`、`GetFan1Speed`、`GetFan2Speed` 和 `GetFanMaxSpeed`，不修改风扇模式或电源设置。原生 WMI 返回对象可只有 `Data`；若存在 `ReturnValue`，必须为布尔成功。数值 0 是停转，缺失、失败或过期是未知。

采样沿用后台线程，成功后至少间隔 2 秒，失败后间隔 30 秒重试。面板隐藏或完全遮挡时暂停。原生 WMI 查询保证实例路径可定位，并对枚举和方法结果设置 500 ms 等待界限；本地命名空间连接由 Windows 管理。来源：[IWbemServices::ExecQuery](https://learn.microsoft.com/en-us/windows/win32/api/wbemcli/nf-wbemcli-iwbemservices-execquery)。

动效取两只已成功读取风扇的较高 RPM。转速与固件参考上限的比例映射到每秒 0.15–2.5 圈，加减速平滑过渡；图标转速是视觉映射，不是按物理 RPM 每转一圈。上限只标为固件参考，不把它当作已验证的机械极限。不根据 CPU 占用率、温度或噪声估算 RPM。不推断风扇 1/2 对应哪个芯片。任一读数失败时不继续表现为正常运行。

## GPU 柱与托盘指标（2026-10-11）

界面参考上游 [v0.2.5](https://github.com/Nongfsq/ftop/releases/tag/v0.2.5)，指标切换参考 [v0.2.2](https://github.com/Nongfsq/ftop/releases/tag/v0.2.2)。

- GPU 柱填充来自同一 NVML 快照的 GPU 占用（0–100%）。0% 不绘制填充；未知显示短横线。启用动画时，柱体平滑追随采样值，数字显示当前样本。
- 频率横线 = 当前 graphics 时钟 / NVML 报告的最高 graphics 时钟，限于 0–1。最高值只在设备初始化时查询，不使用常量猜测。不支持最高频率时省略横线，详情仍显示可读的当前频率。来源：[NVIDIA NVML Device Queries](https://docs.nvidia.com/deploy/nvml-api/latest/api/group__nvmlDeviceQueries.html)。
- 托盘内存百分比 = 已用物理内存 / 总物理内存 × 100；GPU 百分比沿用 NVML；CPU 百分比沿用整机口径；网络沿用实际时间间隔的字节计数差分；功耗沿用 CPU 封装 RAPL。界面不会把 CPU 功耗命名为整机功耗。
- 托盘数字为舍入展示，悬停给出指标与单位。网速 K/M/G 为十进制 B/s 单位；没有把 bit/s 与 B/s 混用。
- 面板不可见时不枚举进程或查询各核心频率。所选指标的后端继续采样，网络和 RAPL 恢复时先建立基线；不展示暂停前的旧读数。托盘数字不变时只更新提示文字，不重建图标。


### 风扇颜色（2026-10-13）

图标颜色表示较高风扇转速占固件参考上限的比例：40% 以下冷蓝，40%–70% 经青绿逐渐过渡到橙色，70%–90% 橙色，90%–100% 逐渐转红。超过参考值按 100% 显示；未知、过期或缺少参考上限时灰色。颜色采用约 0.65 秒时间常数平滑过渡，关闭动效时直接更新颜色；温度文字保持原色。红色表示高速散热，不表示温度报警。没有新增采集调用或图片资源。

## 可选功耗估算（2026-10-14）

### 温度计颜色

CPU 温度计按真实温度着色：低于 50°C 蓝色，50°C 至低于 65°C 绿色，65°C 至低于 80°C 橙色，80°C 及以上红色。未知或无效读数用灰色。深浅主题使用对应颜色，数字保留原色；不改变传感器、采样频率或窗口布局。这些是显示分档，不代表所有 CPU 的节流或损坏阈值。

### 估算口径

参考模型只存在于显示层；原始 `memoryPower` 优先使用 DRAM 能量计数器，`systemPower` 仍保留未知值。传感器读数始终优先，不受参考估算开关影响。开关默认关闭，参考估算显示 `≈`，未知显示 `—`。手动参数必须同时填写来源，并绑定当前电脑、CPU、内存和 NVML GPU 信息；硬件不匹配时不套用旧参数。

DRAM 路径沿用现有单封装、单处理器组 Comet Lake 型号限制。读取 0x619，单位使用 0x606 的指数，不假定固定能量单位。每次使用独立时间戳与 32 位差分，处理回绕、首次采样和暂停。可选 DRAM 读取失败不会使 CPU 传感器失败，不沿用旧功耗；开启参考估算时可回退到下面的固定模型。RAPL 数值沿用 CPU 的传感器显示格式，详情明确标为硬件估计。

正式应用内嵌官方签名 IntelMCHBAR 0.2.11 模块，以独立句柄提供悬停详情的带宽数据；功耗仍来自 IntelMSR。

带宽读取仅允许 0x5050 与 0x5054 两个偏移，当前限 Intel family 6 / model A5、单封装与单处理器组。内存模块可见且面板活动时约每秒采样；隐藏或仅托盘内存百分比时暂停。首次采样、失败、恢复首帧均显示 `—`，失败最多每 30 秒重试。每个方向使用独立 QPC 中点时间戳。以高于此平台双通道 DDR4 峰值的 128 GB/s 上界约束 32 位回绕窗口；间隔达到约 2.147 秒时放弃差分并重新建立基线。因此较慢的刷新设置可能显示未知，不生成可能混淆多次回绕的速率。此模块失败不影响 CPU、内存功耗或内存容量。

内存自动模型只匹配 Samsung `M471A1K43DB1-*`、单条 8 GiB、DDR4、2133–3200 MT/s，且要求每条都匹配。依据为 [Samsung DDR4 8Gb D-die SODIMM Rev1.1，表 48](https://download.semiconductor.samsung.com/resources/data-sheet/DDR4_8Gb_D_die_Unbuffered_SODIMM_Rev1.1_Jun.18.pdf) 的 2666 MT/s 最大测试模式电流。用 VDD=1.2 V、VPP=2.5 V 计算：

| 工况 | IDD / IPP（mA） | 假设占比 |
| --- | --- | --- |
| 活跃待机 | 216 / 32 | 76% |
| 读 | 720 / 32 | 10% |
| 写 | 664 / 24 | 10% |
| 刷新 | 1480 / 144 | 4% |

每条参考功耗 = 各工况 `(IDD × 1.2 + IPP × 2.5) / 1000` 的加权和，再乘 `实际配置速率 / 2666`。最后汇总全部内存条。例如，两条符合模型条件的 8 GiB 内存按 2933 MT/s 计算时，参考值约为 1.151 W。

这些占比是明确设定的参考工况，没有测量实际读写占空比。速率线性缩放也是近似；表中的最大测试电流不是平均实测值，也不构成整机误差上限。模型不包含终端电阻、稳压损耗等板级开销。内存占用率不是带宽，不能拿已用容量来制造实时功耗波动。因此参考值与图标保持静态；用户输入的内存参考值也遵守此规则。

整机估算 = CPU 封装功耗 + 单块 NVML 独显功耗 + 内存功耗（优先 DRAM 计数器）+ 自动基础功耗。有来源且匹配硬件的手动基础值仍可覆盖自动模型，但不再要求填写。范围为电脑直流侧，不含电池充电、外设和适配器损耗。CPU/GPU/内存任一项不可用、多 GPU 或电脑类别未知时保持未知，不用 TDP 代替实时功耗。

自动模型 `hardware-reference-v1` 使用以下**工程参考假设**。它们不是本机测量、厂商规格、误差界限或统计置信区间。即使所有状态输入已读到，整机仍标为低置信度粗估。

| 部分 | 参考公式（W） |
| --- | --- |
| 主板、芯片组、控制器、无线及内存终端电阻 | 笔记本 5；台式机/工作站 12 |
| 笔记本内置屏幕 | `2 + 4 × 亮度比例`；未知亮度按 70% 参考；台式机不计外接屏幕 |
| 每块内置 SSD | `0.5 + 4.5 × 磁盘忙碌比例` |
| 每块内置 HDD | 笔记本 `2.5 + 3.5 × 忙碌比例`；台式机 `4 + 5 × 忙碌比例` |
| 未知介质的内置磁盘 | 每块 2.5 |
| 风扇 | 每只正在转动的风扇参考 1；停转为 0；读不到时笔记本参考合计 2、台式机 3 |
| CPU/内存供电转换损耗 | `(CPU功耗 + 内存功耗) × (1/0.9 − 1)`，参考效率 90% |

磁盘清单读取失败时按一块 SSD 参考；忙碌比例未知时按 10% 参考。悬停仅保留总值与一句来源、方法说明；缺失项的参考工况在本文列明。聚合磁盘忙碌比例只能做粗略插值，不表示每块盘的独立负载。RPM 不是功耗，不能直接按转速算电功率；本模型只用 RPM 区分停转和运行。GPU 板级功耗已含其供电开销，不再追加相同损耗。内置屏幕未按面板型号、尺寸或刷新率校准；亮度和功耗线性关系也是近似。休眠屏幕、复杂存储、外设和不同电源模式可能增加偏差。

例如，笔记本亮度输入为 70% 时，该模型的屏幕参考项为 4.8 W。Windows 的 [WmiMonitorBrightness](https://learn.microsoft.com/en-us/windows/win32/wmicoreprov/wmimonitorbrightness) 提供亮度百分比；[MSFT_PhysicalDisk](https://learn.microsoft.com/en-us/windows-hardware/drivers/storage/msft-physicaldisk) 提供磁盘类别与总线。启动时读取硬件清单；面板采样活跃时亮度最多每 10 秒读取一次，失败后 30 秒重试，不调亮度或风扇。不会新增后台进程。整机模型没有外部功率计校准，也没有自动电池校准。

原生逻辑自测覆盖真实读数优先、零值、缺失输入、硬件不匹配、多 GPU、开关和暂停。`tests/power_motion.py` 使用独立配置验证原生设置、参数输入、说明、连续帧、尺寸和重启。测试中的 10 W 基础值仅用于验证求和，不能用作本机参考值，亦不会写入日常配置。
